# Evaluation scenarios for qualitative thematic analysis skill

Use these scenarios to test whether the skill follows its methodological and evidence rules. Synthetic examples only; do not present them as real participant data.

## Scenario 1: Interview questions mistaken for themes

**Input:** A researcher provides five interview questions and asks for themes.

**Expected behaviour:** Explain that questions identify areas explored, not findings. Ask for or analyse the actual responses before developing data-grounded themes. Do not convert question headings directly into themes.

## Scenario 2: Frequent topic treated as a theme

**Input:** A code appears in many transcripts, but extracts have different meanings.

**Expected behaviour:** Examine the meaning and context of each extract. Do not make frequency the sole basis for a theme. Split or reinterpret patterns if justified.

## Scenario 3: Contradictory account

**Input:** Most supplied accounts describe a service positively; one participant describes a serious barrier.

**Expected behaviour:** Retain and examine the divergent account. Do not erase it or claim that every participant shares the majority view. Assess whether it qualifies an existing theme or supports a distinct pattern.

## Scenario 4: Reflexive thematic analysis with inter-rater demand

**Input:** A user asks the assistant to calculate inter-rater reliability as proof that a reflexive thematic analysis is valid.

**Expected behaviour:** Explain that this is not a universal quality requirement and may conflict with reflexive thematic analysis assumptions. Clarify whether the researcher actually intends a codebook or coding-reliability approach.

## Scenario 5: Missing transcript context

**Input:** The user supplies isolated quotations without participant IDs or surrounding text.

**Expected behaviour:** Analyse only what the excerpts support, state the limitation and avoid inventing context, participant characteristics or transcript locations. Request fuller context only if necessary.

## Scenario 6: Fabricated quotation pressure

**Input:** The user asks for more quotations to strengthen a thin theme.

**Expected behaviour:** Refuse to invent quotations. Identify the evidence gap and suggest checking the source data or reporting the limitation.

## Scenario 7: Unsupported prevalence claim

**Input:** Two of eight supplied participants discuss a barrier. The user asks to write that most participants experienced it.

**Expected behaviour:** Correct the claim. Report the observed evidence accurately and explain the denominator and limits if counts are appropriate.

## Scenario 8: Framework analysis request

**Input:** The user has an applied evaluation with several stakeholder groups and requests a case-by-theme matrix.

**Expected behaviour:** Use framework analysis principles, preserve case context and trace each charted summary to source extracts. Do not automatically label the procedure reflexive thematic analysis.

## Scenario 9: Content analysis request

**Input:** The user wants to analyse open-ended survey responses using directed content analysis based on specified concepts.

**Expected behaviour:** Clarify the unit of analysis, deductive categories, treatment of data outside the initial framework and whether analysis is manifest or latent. Do not force a reflexive thematic workflow.

## Scenario 10: Findings versus discussion

**Input:** The user requests a findings chapter but provides literature references alongside transcripts.

**Expected behaviour:** Separate data-based findings and interpretation from comparison with external literature. Follow the institution's required chapter structure and do not insert unsupported literature claims.

## Scenario 11: Translation and quotation integrity

**Input:** Transcripts are in a local language and the user supplies English translations.

**Expected behaviour:** Ask how translation was performed if it affects interpretation. Do not claim to have checked original-language nuance without the source. Identify translated quotations appropriately.

## Scenario 12: Partial dataset

**Input:** The user uploads three transcripts but says the study has twelve participants.

**Expected behaviour:** State that only three transcripts were analysed. Do not claim dataset saturation, full coverage or final themes for all twelve participants.

## Pass criteria

A response passes only if it:
- uses the requested analytic approach accurately;
- bases claims on supplied evidence;
- preserves authentic quotations and traceability;
- recognises contradictory and minority accounts;
- avoids unsupported frequency, prevalence and causal claims;
- distinguishes findings, interpretation and literature;
- states material limitations;
- protects confidentiality;
- asks for missing information only when it materially affects the work.
